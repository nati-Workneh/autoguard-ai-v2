# AutoGuard AI

AutoGuard AI predicts whether an insurance policyholder will file a claim and supports consistent underwriting review decisions, with human review retained for probabilities above the business threshold.

## Dataset

The single authoritative dataset is `02_Data/Car_Insurance_Claim_50000_FINAL.csv` with 50,000 records. The ML workflow creates duplicate-safe Train, Validation, and Test partitions directly from this file — no separate pre-split files are kept.

## Machine learning

Open `01_ML_Model/AutoGuard_AI_Final_ML_Pipeline.ipynb` (Google Colab or local Jupyter). It contains the complete ML workflow, top to bottom: data-quality checks, EDA (with figures saved to `01_ML_Model/figures/`), feature selection, leakage-safe splitting, preprocessing, a baseline, Logistic Regression, Random Forest, three PyTorch neural-network architectures (different layer counts, neuron counts, activations, and a Dropout(0.30) variant), unified Validation model comparison, threshold analysis, one-time final Test evaluation, bootstrap confidence intervals, feature importance, and error analysis.

The official model is `01_ML_Model/model_v2.pkl`; its metadata — generated by the notebook run, not hand-typed — is `01_ML_Model/model_v2_metadata.json`. The current final model is Random Forest, selected on Validation ROC-AUC, evaluated once on Test at a threshold of 0.35:

| Metric | Test result |
|---|---|
| Accuracy | 0.8546 |
| Precision | 0.7131 |
| Recall | 0.8966 |
| F1 | 0.7944 |
| ROC-AUC | 0.9350 |
| PR-AUC | 0.8562 |

## Run

```powershell

jupyter nbconvert --to notebook --execute --inplace 01_ML_Model/AutoGuard_AI_Final_ML_Pipeline.ipynb

python 05_Gradio_Interface/gradio_app.py

# Production interface (FastAPI backend + web frontend)
Set-Location 06_Production_Interface
uvicorn backend.main:app --reload
Set-Location ..

# Economic model (ROI, thresholds, scenarios)
python 07_Economic_Model/economic_model.py
```

The production UI is served at `http://127.0.0.1:8000`; the active health endpoint is `/api/v2/health`.

## Model Input Domain

The production interface and Gradio demo validate three numerical inputs (past accidents, speeding violations, DUIs) against the range represented in the model's training dataset. Tree-based models like Random Forest do not reliably extrapolate beyond their fitted split regions, so inputs outside that range are not treated as ordinary predictions: the model's real, unmodified probability is still shown, alongside a clear warning that the estimate falls outside the model's supported domain and the case should be routed to manual review.

| Field | Supported range |
|---|---|
| Past accidents | 0-15 |
| Speeding violations | 0-22 |
| DUIs | 0-6 |

See `06_Production_Interface/backend/input_domain.py` for the single source of truth these ranges are drawn from.

## Reproducibility

Every run is seeded (`SEED = 42`, applied to Python, NumPy, PyTorch, and every scikit-learn estimator). Re-running the notebook regenerates `model_v2.pkl` and `model_v2_metadata.json` from the same 50,000-row dataset; the Gradio app, production backend, and economic model all read those two files directly, so re-running the notebook is the single step needed to refresh every downstream number in this repository.
